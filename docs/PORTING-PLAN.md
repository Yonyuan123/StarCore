# PCL-CE / HMCL 功能移植计划（SCL 启动器）

**原则**：只移植功能与交互思路，不复制任何代码；界面始终用 SCL 自己的设计语言。
**节奏**：每批一个版本（1.1.0 → 1.2.0 → …），批批可验收。
**交付**：每批完成后**同时**更新两处 ——
①仓库 `dist/`（本地直接双击 `dist/StarCore-win-x64/StarCore.exe`，不用去 GitHub 下载）；
②GitHub Releases（线上分发）。
**质量**：每批跑完 前端静态检查 → 编译 → 界面资源哈希校验 → 包内容校验 四道闸才发版。

> 前置结论：**版本隔离**在我们的架构里天然成立 —— 每个实例是独立目录
> （`instances/<id>/` 内含 mods / saves / config / resourcepacks 全套），
> 启动工作目录就是实例路径（`LaunchService` 的 `WorkingDirectory = inst.Path`）。
> 与 PCL 的"版本隔离"效果完全一致，无需移植，只需在界面上标注清楚（第 1 批做）。

## 第 1 批 · 下载源测速与实例隔离标注（v1.1.0）

- **下载源测速**（PCL 的经典能力）：对官方源 / BMCLAPI / 自定义源逐个探测延迟，
  一键选最快。内核新增 `source.ping`，设置页加「测速」按钮与结果展示。
- **版本隔离标注**：实例概览页明确显示「此实例完全隔离」及其含义，
  把已有能力从"隐性正确"变成"显性可信"。

## 第 2 批 · Java 中心（v1.2.0，HMCL 强项）

- 手动添加任意 Java 目录（现在只有自动发现）
- Java 运行自检（`java -version` 实测，探测失败给出的不再是"没找到"而是具体原因）
- 按实例锁定 Java（覆盖全局自动选择）
- 内存与 JVM 参数模板（预设：整合包 / 模组轻量 / 模组重量）

## 第 3 批 · 存档管理（v1.3.0）

- 存档列表：读取 level.dat 显示 游戏模式 / 种子 / 最后游玩时间 / 版本
- 备份与恢复（含"启动前自动备份"开关，PCL 的招牌安全感）
- 单世界删除 / 重命名 / 在文件夹中显示

## 第 4 批 · 启动体验（v1.4.0，PCL 招牌）

- 启动倒计时与二次确认（防止误点）
- 游戏窗口标题自定义（支持变量：实例名 / 版本）
- 启动后自动隐藏启动器、游戏退出后自动弹出（`LaunchCloseLauncher` 已有字段，补实现）
- 分辨率与全屏预设

## 第 5 批 · 整合包（v1.5.0，体量最大单独一批）

- CurseForge zip 导入（解析 manifest.json）
- 导出为标准 .mrpack（Modrinth 格式）
- 整合包信息展示（图标 / 简介 / 作者）

## 第 6 批 · 崩溃诊断（v1.6.0，HMCL 强项）

- 崩溃报告自动归类（缺模组 / 版本不匹配 / Java 错误 / 内存不足 四大类起步）
- 常见原因知识库 + 一键跳转解决方案
- 崩溃后自动打开诊断页而非静默退出

## 第 7 批 · 已安装内容强化（v1.7.0）

- 模组升级检查（Modrinth 有新版本时提示）
- 依赖冲突提示（同 id 不同文件的重复模组）
- 批量启用 / 禁用 / 删除

## 第 8 批 · 账户与皮肤（v1.8.0）

- LittleSkin / 任意 Blessing Skin 站登录（Yggdrasil 协议）
- 皮肤预览（2D 大图 + 3D 简易渲染）
- 离线账户皮肤（本地文件）

## 第 9 批 · 自动更新落地（v1.9.0）

- 应用内一键更新（下载 → 校验哈希 → 替换 → 重启）
- 更新日志在应用内展示
- 降级保护（跳版本更新时警告）

## 第 10 批 · 打磨（v2.0.0 前最后一站）

- 快捷键体系（全局呼出 / 快速启动）
- 首次使用引导
- 设置搜索
- 性能剖析与启动耗时优化

## 明确不做

- 联机 / 局域网房间（体量与维护成本远超启动器范畴）
- 自动安装 OptiFine（无公开接口，引导用户手动下载）
- 任何形式的盗版 / 绕过验证

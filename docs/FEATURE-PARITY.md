# 功能差距清单与分批计划

> 目标：把 PCL-CE / HMCL 的功能面系统性地覆盖到 StarCore 上。
> 本文档是**评审用**的清单 —— 先对齐"差什么、值不值得做、按什么顺序做"，
> 再动手，避免闷头做完方向不对。

## 怎么读这份清单

- **缺口**列的是 PCL-CE / HMCL 有、而 StarCore 现在没有或明显弱的能力。
- **价值**按"普通玩家的日常路径"评估，不是按功能数量：
  `高` = 不做就会被认为"这启动器不完整"；`中` = 特定人群会频繁用到；`低` = 长尾。
- **成本**按实现与验证的总量估：`小` = 一两处内部改动；`中` = 新增服务 + 页面；
  `大` = 跨模块、需要新协议或新外部依赖。
- 每批都尽量做到**批内可交付**：做完一批就能发一版，不留半成品。

## 二、分批计划

排序原则：**先补齐"日常路径上的洞"，再做长尾；外部依赖项单独列出、不阻塞主线。**

### 第 1 批 —— 把日常路径补完整（建议先做这批）

| 项 | 内容 |
|---|---|
| E3 | 第三方皮肤库登录（LittleSkin / Blessing Skin，Yggdrasil 协议）+ 让它真正生效 |
| A8 | 文件完整性校验（sha1），装完能自证完整 |
| A7 | 安装前磁盘空间检查 |
| D3 / D4 | 日志过滤与搜索；崩溃报告聚合展示 |
| C1 / C2 | 存档与截图的图形化管理（浏览 / 备份 / 打开目录） |

**为什么是这几项**：它们全部落在"装完 → 玩 → 出问题 → 修"这条主线上，
且都不引入新的外部协议依赖，风险低、可一小步一小步验证。

### 第 2 批 —— 下载与 Java 的可控性

| 项 | 内容 |
|---|---|
| A1 / A2 | 下载源管理面板 + 测速 + 自定义源校验 |
| B4 | 全局 JVM 参数模板（含 Aikar's flags 等预设） |
| B3 | 更贴近实际的内存建议（按版本 + 模组量） |
| C4 | 模组重复 / 冲突检测 |
| C6 | 存档自动备份 |
| F4 | 关闭到托盘等宿主交互核对完整 |

### 第 3 批 —— 整合包（体量最大，单独一批）

| 项 | 内容 |
|---|---|
| A3 | CurseForge / Modrinth / 本地 zip 的完整导入：加载器识别、overrides 覆盖、并发下载、进度可视化 |
| A4 | 整合包导出 |
| C7 | 实例导入导出打包 |

**这一批要单独排期**：整合包格式的实际变体远多于文档描述，
必须先拿真实包做兼容性矩阵，否则会陷入"每次都有新格式"的被动修补。

### 独立轨道 —— 不阻塞主线的外部依赖

| 项 | 内容 |
|---|---|
| E1 | 微软登录：等待 <https://aka.ms/mce-reviewappid> 审核结果。**通过后无需改代码**。 |
| E4 | authlib-injector 支持：需要引入并校验一个第三方 jar，且要处理"启动参数注入 + 版本隔离"，建议在 E3 稳定后单独做。 |
| F7 | 安卓版：内核已解耦，属于独立宿主工程，不影响桌面端迭代。 |

## 三、明确的**不做**清单

以下能力**不打算做**，写在这里是为了避免反复讨论：

| 不做 | 原因 |
|---|---|
| 任何形式的盗版 / 破解 / 绕过正版验证 | 违反 EULA 与使用准则，会被 Mojang 拒绝接入且可能导致项目被下架 |
| 分发 Minecraft 游戏文件本身 | 同上；所有游戏内容一律由用户从官方源下载 |
| 隐藏或修改 Minecraft 自带对话框（含 EULA、警告、错误） | 使用准则明确禁止 |
| OptiFine 自动安装 | 官方无公开直链；推荐 Iris + Sodium |
| LiteLoader | 多年未更新，无可用自动安装方式 |
| 内置"别人的"已获批 Azure 应用 ID | 以他人应用身份请求他人可见，且随时可能被撤销；必须走正规申请 |
